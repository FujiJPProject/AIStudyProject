# AI学習用HTML作成 Skill

## 1. 目的

ユーザーから学習項目を指定され、
「この内容を学習できるHTMLファイルを作成して」
と依頼された場合に、初心者がブラウザ上で理解・操作・確認できる
**自己完結型のHTML教材**を作成する。

このSkillでは、`ai-learning-template.html` を
教材デザイン・図解方針・インタラクション・クイズ体験の
共通基準として扱う。

---

## 2. 基準ファイルと役割

### 2.1 `ai-learning-template.html`

新規教材作成時の**直接のベーステンプレート**とする。

原則として以下を継承する。

- HTMLの基本構造
- 配色
- CSS変数
- コンテンツ幅
- ヘッダー
- カード
- 学習ゴール
- 定義ボックス
- 具体例
- 図解
- 表
- 演算・処理ステップ
- インタラクティブ操作
- クイズ
- まとめ
- レスポンシブ対応
- JavaScriptによるフィードバック方式

---

## 3. 最重要ルール

### 3.1 各HTMLは同一シリーズとして扱う

各教材は独立したWebサイトではなく、

**同一シリーズ内の1レッスン**

として作成する。

したがって、学習テーマが変わっても以下を勝手に変更しない。

- ブランド
- カラーパレット
- ページ幅
- 基本余白
- カード形状
- 影
- 見出し階層
- ボタン形状
- クイズUI
- フィードバック方法
- レスポンシブ方針

### 3.2 改善より継承を優先する

既存デザインについては
**「改善」ではなく「継承」**をデフォルトとする。

ユーザーから明示的な変更指示がない限り、
再設計、モダナイズ、別テーマ化、別フレームワーク化を行わない。

### 3.3 学習内容に合わせて中身を変える

固定するのはデザインシステムであり、
教材内容まで機械的に固定してはいけない。

テーマごとに以下は最適化してよい。

- 説明順序
- 具体例
- 数式
- 図の種類
- 比較表
- 操作項目
- 練習問題
- クイズ内容
- AIとの接続説明

---

## 4. 共通デザイン仕様

`ai-learning-template.html` のCSSを基準とする。

### 4.1 基本カラーパレット

原則として以下を維持する。

```css
--bg: #f6f8fc;
--card: #ffffff;
--text: #1f2937;
--muted: #667085;
--accent: #3157d5;
--accent-dark: #243b88;
--accent-soft: #eef2ff;
--border: #dfe5f0;
--good: #137333;
--bad: #b42318;
--warning: #b54708;
--shadow: 0 10px 28px rgba(31, 41, 55, 0.08);
```

### 4.2 レイアウト

原則として以下を維持する。

- 最大コンテンツ幅: 約980px
- 左右余白: 16px以上
- カード間隔: 約24px
- カード角丸: 約18px
- 内部ボックス角丸: 約14px
- モバイルでは複数カラムを1カラム化

### 4.3 ヘッダー

教材タイトルは、
`ai-learning-template.html` と同系統の
青系グラデーションヘッダーを使用する。

ヘッダーには以下を含める。

- 上位カテゴリ / 分野
- 学習項目名
- この教材で学ぶ内容の短い説明

---

## 5. 教材の基本構成

原則として次の順序で構成する。

1. ヘッダー
2. この学習のゴール
3. 基礎概念・定義
4. 具体例
5. 図解
6. AI・機械学習・LLMとの関連
7. 基本操作・計算・処理
8. 必要に応じた追加図解
9. インタラクティブな操作・計算
10. 確認クイズ
11. まとめ・到達目標

ただし、学習テーマ上不要なセクションを無理に入れてはいけない。

重要なのは、次の4点が学習後に答えられることである。

- **何か**
- **なぜ必要か**
- **どう扱うか**
- **AIでどう使われるか**

---

## 6. 図解ルール

### 6.1 図で説明できる内容は原則図示する

文章や数式だけより理解しやすくなる場合は、
**図を必ず検討する。**

特に以下は図解対象とする。

- ベクトルの方向・大きさ
- 座標
- 行列変換
- 内積と角度
- 関数の形
- 微分の傾き
- 確率分布
- ニューラルネットワークの層
- forward / backward の流れ
- Attentionの参照関係
- Transformerブロック
- Token → Embedding の変換
- 学習処理のデータフロー
- 入力 → 処理 → 出力
- 複数概念の比較
- 時系列の変化

### 6.2 図解方法

外部画像に依存せず、
可能な限り以下を使用する。

1. HTML + CSS
2. SVG
3. Canvas
4. JavaScriptによる動的描画

数学・座標・矢印・処理フローは
**SVGを優先**する。

### 6.3 図の説明

図を置くだけでは不十分。

各図には原則として以下を付ける。

- `.diagram-title` によるタイトル
- 図内のラベル
- `.note` による読み方・重要ポイント

ユーザーが「何を見るべき図なのか」を判断できるようにする。

### 6.4 図のスタイル

原則としてテンプレート内のクラスを使用する。

- `.diagram`
- `.diagram-title`
- `.axis`
- `.gridline`
- `.vec-blue`
- `.vec-green`
- `.vec-orange`
- `.dash`
- `.svgtext`
- `.svgstrong`

新しい色を増やす必要がある場合も、
既存カラーパレットから派生させる。

---

## 7. 数学教材ルール

数学教材では、
**数式だけを掲載して説明を終えてはいけない。**

必ず可能な範囲で以下を組み合わせる。

1. 日本語による直感的説明
2. 定義
3. 数式
4. 具体的な数値例
5. 図解
6. 手計算の流れ
7. 操作できる計算例
8. AIでの用途

例として、`[3, 2]` というベクトルを扱う場合は、

- 3と2が何を意味するか
- 2次元平面ではどう見えるか
- 矢印ではどう表せるか
- AIでは何に対応するか

まで接続して説明する。

---

## 8. AIとの関連説明

すべての教材で、
可能な限りAI・機械学習・LLMとの接続を説明する。

ただし、無理な関連付けはしない。

関連がある場合は以下のレベルで説明する。

### レベル1: 直近の用途

例:

- ベクトル → 特徴量
- 行列 → 線形変換
- 微分 → 勾配
- 確率 → 予測分布

### レベル2: 機械学習

例:

- 勾配降下法
- ニューラルネットワーク
- 損失関数
- 埋め込み

### レベル3: LLM

例:

- Embedding
- Attention
- Q/K/V
- Transformer
- Logits
- Softmax
- Cross Entropy

現在の項目が後続学習のどこにつながるのかを示す。

---

## 9. インタラクティブ要素

### 9.1 原則

操作することで理解が深まるテーマでは、
JavaScriptによる小さな実験環境を用意する。

`ai-learning-template.html` のインタラクティブ教材UIを基準とする。

### 9.2 適した例

- スカラー: 値を変えて計算
- ベクトル: 加算、減算、内積、大きさ
- 行列: 行列積、ベクトル変換
- 関数: 入力値と出力値
- 微分: xを変えて傾きを確認
- 活性化関数: 入力と出力を比較
- Softmax: logitsを変えて確率変化を確認
- 損失関数: 予測を変えてlossを確認
- Attention: スコアや重みを変化させる
- Gradient Descent: 学習率による更新差を確認

### 9.3 結果表示

結果は単なる数値だけでなく、

- 計算結果
- 途中式
- その値の意味

のうち可能なものを表示する。

---

## 10. クイズルール

原則として1教材に複数問の確認クイズを入れる。

最低限、次の観点から出題を検討する。

1. 定義
2. 計算・操作
3. 図の理解
4. AIとの関連

### 10.1 UI

`ai-learning-template.html` と同様に、

- 選択肢ボタン
- 回答後のロック
- 正解 / 不正解の色分け
- フィードバック文
- リセットボタン

を基本とする。

### 10.2 解説

「正解です」「不正解です」だけで終わらせず、
可能な限り短い理由・ヒントを表示する。

---

## 11. コンポーネント継承ルール

新しいUIが必要な場合は、
既存デザインシステムから派生させる。

### 既存コンポーネント

- `.card`
- `.goal`
- `.definition`
- `.example-grid`
- `.example`
- `.label`
- `.note`
- `.table-wrap`
- `.op`
- `.diagram`
- `.playground`
- `.inputs`
- `.input-block`
- `.buttons`
- `.result`
- `.quiz`
- `.answers`
- `.answer`
- `.feedback`
- `.summary`
- `.checklist`

### 新規UI作成時

以下を守る。

- 背景色は既存CSS変数を使用
- borderは `--border` を優先
- radiusは既存の10〜18px程度に合わせる
- shadowは `--shadow` を使用
- primary actionは `--accent`
- successは `--good`
- errorは `--bad`
- 新規フォントを勝手に導入しない

---

## 12. CSS変数の扱い

既存HTMLで定義されているCSS Custom Propertiesは、
原則として値を変更しない。

新規コンポーネントでもCSS変数を使用し、
色・影・余白・角丸を大量に直接ハードコードしない。

ただしSVG内部で互換性や可読性のために
同じ既存色を直接記述することは許容する。

---

## 13. レスポンシブ要件

最低限、PCとスマートフォンで利用できること。

モバイルでは、

- `.goal`
- `.example-grid`
- `.inputs`

などの複数カラムを1カラムにする。

SVGは横幅が不足する場合、
`.diagram` 内で横スクロール可能にする。

表は必要に応じて `.table-wrap` で横スクロール可能にする。

---

## 14. アクセシビリティ・可読性

可能な限り以下を守る。

- SVGに `role="img"` または `aria-label`
- ボタンは意味が分かるテキストにする
- 色だけに意味を依存しすぎない
- 数式の前後に文章説明を置く
- 小さすぎる文字を避ける
- 長文はカード・図・例に分割する

---

## 15. 自己完結型HTML

原則として1ファイルで動作する教材を作成する。

可能な限り、

- CSSは `<style>` 内
- JavaScriptは `<script>` 内
- 図はSVG / Canvas
- 外部CDNは使用しない
- 外部画像に依存しない

とする。

ユーザーから別途指示された場合のみ、
複数ファイル構成を使用する。

---

## 16. デザイン変更の許可範囲

### 変更してよい

- 学習タイトル
- 分野名
- 説明文章
- 定義
- 数式
- 図解内容
- SVGの座標・形
- 具体例
- 表の内容
- 操作内容
- JavaScriptの計算ロジック
- クイズ
- まとめ
- テーマ固有の追加UI

### 原則変更しない

- 全体カラーパレット
- 最大ページ幅
- ヘッダーの基本スタイル
- カードのデザイン
- ボタンの基本スタイル
- クイズの基本UI
- まとめカードの基本UI
- フォントファミリー
- レスポンシブ方針

---

## 17. デザイン優先順位

判断が衝突した場合は以下の順番で優先する。

1. ユーザーが今回明示した指示
2. ユーザーが「参考にする」と指定した既存教材
3. 直前に作成した同シリーズのHTML
4. `ai-learning-template.html`
5. この `SKILL.md`
6. AIによる一般的なWebデザイン判断

---

## 18. ファイル作成手順

新しい教材を作成するときは次の順番で処理する。

1. ユーザーが提供した学習項目を確認
2. 参考HTMLがある場合は解析
3. `ai-learning-template.html` のデザイン構造を確認
4. 学習後の到達目標を3点程度に整理
5. 「何か」「なぜ必要か」「どう扱うか」「AIとの関連」を整理
6. 図解可能な箇所を洗い出す
7. 具体例を設計
8. 数式・計算・処理手順を設計
9. インタラクティブ要素が有効か判断
10. クイズを設計
11. テンプレートへ内容を反映
12. JavaScriptを実装
13. モバイル表示を確認
14. デザイン統一性を確認
15. 完成HTMLとして出力

---

## 19. 禁止事項

以下を行わない。

- 毎回ゼロから別デザインを作る
- テーマごとにカラーパレットを変える
- 「見栄えを良くするため」だけで既存デザインを変更する
- Bootstrap、Tailwind等へ勝手に置き換える
- 外部画像を必須にする
- 図で説明しやすい内容を文章だけで済ませる
- 数式だけ提示して説明を省略する
- AIとの関連を単語だけ並べて済ませる
- 操作可能なテーマなのに静的説明だけで終える
- クイズの正誤だけ表示して解説を一切付けない
- PCでしか使えないレイアウトにする
- 学習項目と無関係な高度内容を大量に追加する

---

## 20. 最終確認チェックリスト

完成前に以下を確認する。

### デザイン

- [ ] `ai-learning-template.html` と同じシリーズに見える
- [ ] 色が統一されている
- [ ] カードデザインが統一されている
- [ ] ボタンデザインが統一されている
- [ ] 最大幅・余白が統一されている
- [ ] モバイルでも崩れない

### 学習内容

- [ ] 学習項目の定義を説明している
- [ ] 初心者向けの直感的説明がある
- [ ] 具体例がある
- [ ] 必要な数式・計算がある
- [ ] AIとの関連が説明されている
- [ ] 到達目標と内容が一致している

### 図解

- [ ] 図で説明できる箇所を検討した
- [ ] 必要な図が入っている
- [ ] 図にタイトルがある
- [ ] 図の読み方・意味が説明されている
- [ ] 小画面でも閲覧できる

### 操作・確認

- [ ] 操作型教材が有効ならプレイグラウンドがある
- [ ] 入力エラーを最低限処理している
- [ ] 計算結果の意味を説明している
- [ ] 確認クイズがある
- [ ] クイズにフィードバックがある
- [ ] リセットできる

すべて確認したうえでHTMLファイルを完成とする。
